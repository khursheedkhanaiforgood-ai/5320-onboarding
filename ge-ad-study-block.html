Hour 1  ·  0:00 – 1:00 ExtremeGuest Essentials

What Is ExtremeGuest Essentials?

ExtremeGuest Essentials is a cloud-hosted guest lifecycle management service. It wraps your open SSID with a branded registration portal, identity capture, time-limited access, and analytics. It does not replace your network policy — it runs as an identity layer on top of the AP and VLAN infrastructure you already built.

The AP handles RF. SW1 handles VLANs. Guest Essentials handles identity.
LayerOwnerResponsibility
Wireless (RF)AP1 + network policyBroadcast KhKLab_Guest, 802.11 association
Network (VLAN / DHCP)SW1VLAN 10, DHCP 10.10.0.x, IP forwarding
Identity (portal)Guest EssentialsSplash page, registration, expiry, analytics

GE lives in the ExtremeCloud IQ cloud. The AP does not host the portal — it acts as a redirect proxy. The guest device stays in a pre-auth state (VLAN 1) until GE signals authentication complete, at which point AP1 re-associates the client to VLAN 10 via the post-auth VLAN override.

Prerequisite completed May 20

The CWP post-authentication VLAN override is already set: EP1 → KhKLab_Guest → CWP → post-auth → force VLAN 10. Without this, the guest stays on VLAN 1 even after GE registration completes. Confirmed working May 20.

Why VLAN switches from 1 to 10 at step 8

Steps 1–5 are on VLAN 1 — the device needs an IP to reach the splash page. At step 8, AP1 re-associates the client to VLAN 10 because of the post-auth VLAN override set May 20 (EP1 → KhKLab_Guest → CWP → post-auth → force VLAN 10). Without that override, the client stays on VLAN 1 even after GE completes successfully.

Hour 2  ·  1:00 – 2:00 AirDefense Essentials

What Is AirDefense Essentials?

AirDefense Essentials is ExtremeCloud IQ's cloud-based WIDS/WIPS — Wireless Intrusion Detection and Prevention System. Your AP3000 acts as a sensor, scanning RF channels and reporting anomalies to the AirDefense cloud engine. Results appear in a dedicated dashboard inside XIQ Classic.

AP1 sees the RF. AirDefense Essentials understands it.
TermDefinition
WIDSWireless Intrusion Detection — sees threats, raises alarms, takes no automated action
WIPSWireless Intrusion Prevention — sees threats AND can terminate rogue devices
Radio-Share SensorAP serves clients AND scans for threats on the same channels simultaneously
Dedicated SensorAP in monitor-only mode — full-time scanning, no client service, sees all channels
Rogue APAn AP not owned by your org — detected by BSS MAC falling outside your AP's assigned range
Evil TwinA rogue AP broadcasting your SSID name — impersonation attack
Contain / TerminateAirDefense sends 802.11 deauth frames to disconnect clients from a rogue AP
SanctionMark a known device (e.g. neighbor's router) as trusted so it stops generating rogue alarms

5-Step Config Sequence

Step 1 — Subscribe

XIQ → Essentials → Extreme AirDefense Essentials → Subscribe

One-time activation on your Pilot account. AirDefense Overview loads after subscribing.

Step 2 — Create WIPS Policy with AirDefense enabled

XIQ main → Configure → Common Objects → Security → WIPS Policies → + Add
FieldValue
NameKhKLab_WIPS
Enable AirDefense EssentialsToggle ON ← the critical setting
Allow channel change for authenticationLeave off for lab

Save.

Step 3 — Assign WIPS Policy to Network Policy

Configure → Network Policies → AP1_ViaEP1_VLAN5-10_PPSK_5 → Additional Settings → WIPS

Select KhKLab_WIPS → Apply → Save.

Step 4 — Push to AP1

Manage → Devices → AP1 → Deploy Policy → Update → Complete Configuration Update → Perform Update

Wait for green audit icon. AP1 reboots and connects to AirDefense cloud in 3–5 minutes.

Step 5 — Optional: Reduce home-lab noise

AirDefense app → Settings → Alarm Management → Reconnaissance → Disable

Reconnaissance alarms fire constantly from neighbor phones and IoT devices in a home lab. Disabling this category removes the noise so you can focus on Exploits and Rogue Activity.

Sanctioning a known device

Alarms → select checkbox on Rogue AP alarm → Classify icon → Yes, Sanction

Device added to sanctioned list — stops generating rogue alarms. Use for neighbor routers that keep appearing. Then: Alarms → Sync Rogue Sanctioned Alarm to set those alarms to INACTIVE.

Hands-On Exercise

Exercise — Work Through in XIQ While Reading

  • Subscribe: XIQ → Essentials → Extreme AirDefense Essentials → Subscribe. Confirm Overview loads with Overview / Alarms / Sensors / Settings in left nav.
  • Create WIPS policy: Configure → Common Objects → Security → WIPS Policies → + → KhKLab_WIPS → Enable AirDefense Essentials = ON → Save.
  • Assign to network policy: Configure → Network Policies → policy → Additional Settings → WIPS → select KhKLab_WIPS → Save.
  • Push to AP1: Manage → Devices → AP1 → Deploy → Complete Configuration Update → Perform Update. Confirm green audit icon.
  • Verify sensor: AirDefense → Sensors. Confirm AP1 shows ONLINE (green), Last Seen within last 2 min, Alarms count starts populating.
  • Wait 5 min then check Overview: Alarms Overview widget shows > 0 alarms. Alarm Count by Severity shows a breakdown.
  • Open an alarm: Alarms → Live Alarms → click any row → read Alarm Detail. Identify: Raised Against MAC, Reported By, Category, Severity.
  • Reduce home-lab noise: Settings → Alarm Management → Reconnaissance → Disable. Confirm alarm count drops.
  • Sanction a neighbor device: Find Rogue AP alarm → checkbox → Classify → Yes, Sanction. Confirm it no longer appears.

Expected alarm types in a home lab

Most alarms will be Info / Minor Reconnaissance from neighbor devices. NetBIOS Traffic and ID Theft Sequence are extremely common in mixed home networks — these are not real attacks. A Rogue AP alarm for a neighbor's router is normal — sanction it once identified.
