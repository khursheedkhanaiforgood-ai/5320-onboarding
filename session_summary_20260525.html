Two-Agent Architecture

How the Two Agents Divide the Work

The curriculum is operated by two separate Claude Code sessions running in parallel on separate threads. Each session has a defined domain and a shared state file for handoffs.

Architect_CodeAgent
Builds, maintains, and publishes the curriculum site
  • Creates and edits all HTML files in the wifi-80211-mastery repo
  • Manages commits, GitHub Pages, and repo structure
  • Owns MEMORY.md — the global memory index. Only this agent writes to it.
  • Creates new memory files when needed; updates the MEMORY.md index
  • Creates this EOD HTML and links it from 5320-onboarding index pages
  • Reads project_wifi_mastery_progress.md to know curriculum state, but does not edit it during curriculum sessions
Socratic_CurriculumAgent
Teaches the curriculum — one day at a time, Socratic method
  • Reads project_wifi_mastery_progress.md at the start of every session to know which Phase and Day to teach
  • Asks 1–2 Socratic questions; waits for answers; probes gaps before revealing any explanation
  • Uses the lab exercise at the end of the exchange, not the start
  • After each session, writes back to project_wifi_mastery_progress.md only — updates Current State (phase/day advance) and appends a session log entry
  • Does NOT touch MEMORY.md — that is Architect_CodeAgent's domain exclusively
Shared State File
The handoff mechanism between both agents

File: /Users/khukhan/.claude/projects/-Users-khukhan/memory/project_wifi_mastery_progress.md

  • Current State block — Phase N, Day N, Status (NOT STARTED / IN PROGRESS / COMPLETE)
  • Curriculum map — 6-phase status table
  • Handoff notes — lab gear, corpus tiers, prior incident context, knowledge depth
  • Session log — append-only; one entry per session with date, topics covered, gaps noted
  • Pending deliverables — items that flow back to Architect_CodeAgent (e.g. capstone report)
Shared Memory Protocol

How the Handoff Works in Practice

Start of a Curriculum Session

  1. Socratic_CurriculumAgent reads project_wifi_mastery_progress.md
  2. Checks the Current State block: Phase N, Day N
  3. Reads the corresponding day card from the live HTML (e.g. study_phase1_phy.html #day1)
  4. Begins with the Socratic question — no preamble, no lecture

End of a Curriculum Session

  1. Curriculum Agent updates Current State block: advances to next day (or marks phase complete)
  2. Appends a session log entry: date, phase/day, topics covered, any gaps the user struggled with
  3. If a deliverable was produced (e.g. capstone report), notes it under Pending Deliverables for Architect to pick up

Start of an Architect Session (after a curriculum session)

  1. Architect reads project_wifi_mastery_progress.md to see what the curriculum agent did
  2. Picks up any deliverables flagged (e.g. "user produced capstone report — need to publish to HTML")
  3. Does NOT modify the progress file during normal operation — only reads it
Write Boundary Rule

The Critical Boundary

Curriculum Agent write scope: ONE file only — project_wifi_mastery_progress.md

MEMORY.md: Managed exclusively by Architect_CodeAgent. The Curriculum Agent never reads from or writes to MEMORY.md. Violation would corrupt the global memory index shared across all projects.

This boundary was established during the May 25 session after the Architect_CodeAgent incorrectly updated MEMORY.md from a curriculum context. Saved as feedback_curriculum_agent_write_boundary.md so it persists across all future sessions.

Why This Matters

MEMORY.md is a global index used across every project — 5320-onboarding, VOSS simulator, Cisco agent, EP1 engine, and now wifi-80211-mastery. If the Curriculum Agent were to write to it, it could overwrite cross-project pointers or create duplicate entries that corrupt another agent's context. The progress file is the Curriculum Agent's sandbox.

Phase 1, Day 1 — First Question Loaded

Topic: OFDM Symbol Structure & Subcarrier Spacing
Opening question: 802.11ac uses 312.5 kHz subcarrier spacing. 802.11ax dropped that to 78.125 kHz — exactly one quarter. The symbol time grew from 3.2 μs to 12.8 μs as a direct consequence. Why does narrower subcarrier spacing force a longer symbol time — and once you have that 12.8 μs symbol, what problem does it solve that 3.2 μs couldn't, specifically in a dense indoor multipath environment?
