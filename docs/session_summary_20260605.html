Simulator Equations — Complete Reference

Everything the simulator displays traces back to one call chain: compute() → band() → phyR(). Below is the full derivation from user inputs to output numbers.

1 · Demand Mix Model

Five app types contribute demand per active session. The mix weights (Video / Teams / Social / Browse / POS) are set by the user's sliders and normalized to 1.

Per-session demand rates (Mbps)
Video DL = 15.0 Video UL = 0.5
Teams DL = 3.0 Teams UL = 3.0
Social DL = 1.0 Social UL = 4.0
Browse DL = 2.0 Browse UL = 0.1
POS DL = 0.1 POS UL = 0.1
Mix-weighted demand per session (Mbps)
tw = vidW + teaW + socW + broW + posW
mix.vid = vidW / tw /* fraction of demand from video */

demDL = mix.vid×15 + mix.tea×3 + mix.soc×1 + mix.bro×2 + mix.pos×0.1
demUL = mix.vid×0.5 + mix.tea×3 + mix.soc×4 + mix.bro×0.1 + mix.pos×0.1
demTot = demDL + demUL
demTot is the per-active-session aggregate demand used in every band's capacity equation.

2 · Session and Client Counts

Stadium population → active clients per AP
totalSess = round( fans × devMult × wifiAtt )
active = round( totalSess × concur )
perAP = round( active / apCount )

bsSplit = BS_SPLITS[apType][bsMode] /* {g2, g5, g6} fractions */
cli2g = min( round(perAP × split2g), effMaxCli )
cli5g = min( round(perAP × split5g), effMaxCli )
cli6g = min( round(perAP × split6g × g6boost), effMaxCli )
effMaxCli = floor(maxCli × ageoutF) where ageoutF accounts for stale client table entries. g6boost = 1.10 when Enhanced RNR is ON.
Example — 100/100 screenshot: 72,000 fans × 1.4 devices × 0.75 WiFi attach × 0.55 concurrency ÷ 280 APs = ~166 clients/AP on 5G. Stadium total demand = 55,440 active × ~5.2 Mbps/session = 287.1 Gbps.

3 · RF Link — RSSI, Noise, SNR

Signal and noise floor
baseRSSI = −62 + (txPwr − 17) × 0.5 /* dBm; nominal at txPwr=17 dBm */
degNoise = [0, 5, 10, 20, 35][degLevel] /* dB added by degradation scenario */
noiseDBm = −95 + noiseFl + degNoise
rxSopBoost = {−85:0, −75:+3, −65:+6}[rxSop]

baseSNR = baseRSSI − noiseDBm + rxSopBoost

Per-band SNR modifier:
snrMod = { 2.4GHz: −3, 5GHz: 0, 6GHz: +4 }
DCS Lock bonus: +2 dB when dcsLock = ON
Degradation SNR penalty (5GHz): [0, 0, −5, −12, −20][degLevel]

4 · PHY Rate — phyR()

MCS lookup → PHY rate
SNR thresholds (WiFi 7 BE / WiFi 6 HE) per MCS:
BE: MCS13=3, 12=6, 11=9, 10=12, 9=15, 8=18, 7=22, 6=26, 5=30, 4=34, 3=38, 2=42, 1=46, 0=50 dB
HE: MCS11=9, 10=11, 9=14, 8=17, 7=20, 6=24, 5=28, 4=32, 3=36, 2=40, 1=44, 0=44 dB

mcs = highest MCS where SNR ≥ threshold, subject to mcsFloor
MCS12/13 also gated by qam4k toggle (4K-QAM must be ON)

PHY1SS[bw][mcs] — 1-spatial-stream rate table (Mbps) for bw ∈ {20,40,80,160,320} MHz
GI_EFF = { 800ns: ×1.05, 1600ns: ×1.00, 3200ns: ×0.93 }

phyR = PHY1SS[bw][mcs] × ss × GI_EFF[gi]
For AP5060 (4SS), 160MHz, MCS11, GI 1600ns: PHY1SS[160][11] = 1201 Mbps × 4SS × 1.0 = 4804 Mbps raw PHY rate.

5 · Capacity Multiplier — capMult()

capMult() aggregates the efficiency gains from every overhead-reduction feature. It applies to channel utilization, not PHY rate — the gain is in reducing wasted airtime (collision overhead, retransmissions, management frames, multicast floods).

Multiplicative gain from feature set (capped at 2.0×)
OFDMA DL: ON → ×1.35
BSS Coloring: ON → ×1.15
Min Basic Rate: 6M → ×1.00 | 12M → ×1.10 | 24M → ×1.18
Broadcast Filter:ON → ×1.15
MC→UC: ON → ×1.10 (±0.02 for threshold/MBR tuning)
Proxy ARP: ON → ×1.07
Client Isolation:ON → ×1.02
Airtime Fairness:OFF→ ×1.00 | Adaptive → ×1.22 | Strict → ×1.38
Multi-RU: ON → ×1.08
MU-MIMO streams: 1SS→×1.00 | 2SS→×1.10 | 4SS→×1.15 | 8SS→×1.20
TXOP AC_BE: ≥3008µs→×1.05 | ≥1504µs→×1.03
MLO Steering: AI → ×1.04
Ignore BC Probe: ON → ×1.08
WMM AC VO: ON → ×1.02
Fragment Threshold: 256B→×0.80 | 1500B→×0.97 | 2346B→×1.00
RTS/CTS: 1500B→×1.04 | 2347B→×1.02 | OFF→×1.00

capMult = min( product of all above, 2.0 )
The 2.0× ceiling is a physical constraint: MAC optimizations cannot more than double efficiency at the same PHY rate. At golden-set settings, capMult ≈ 1.88 (just below ceiling).

6 · Effective Capacity

Channel capacity after MAC overhead
MAC_EFF = 0.45 /* 55% of channel time lost to DIFS+SIFS+ACK+preamble+backoff */

effCap = phyR(ss, bw, mcs, gi) × 0.45 × capMult
MAC_EFF = 0.45 is a conservative baseline for dense 802.11ax/be at typical frame sizes (1500B PDUs). capMult then recovers a portion of that overhead through OFDMA, BSS Coloring, airtime fairness, etc.

7 · Airtime Utilization

Normalized channel load
demand = clients × demTot /* total Mbps demanded from this band */
u = min(0.98, demand / effCap) /* utilization 0..0.98 */
air = min(150, round(u × 100)) /* displayed as % */
u is capped at 0.98 (never reaches 1.0 — the M/D/1 queueing model diverges at u=1). air can exceed 100% as a warning indicator at overload.

8 · Latency — M/D/1 Queueing Approximation

Aggregate 802.11 latency (ms)
qd = u < 0.05 ? 0.5 : 6u / (1−u) /* M/D/1 queue delay */
lat = 8 + qd /* 8ms = fixed MAC + PHY overhead */

Adjustments (additive, ms):
+ k/v OFF: +10 ms
+ 802.11r OFF + deg≥1: +8 ms
+ TXOP VO active: −4 ms
+ DTIM interval: +(dtim − 1) × 8 ms
+ CWmin=7 + u>0.7: +3 ms
+ U-APSD OFF: +2 ms
+ WMM AC VO OFF: +2 ms
+ WMM AC VI OFF: +1 ms
+ clientAgeout ≥30min: +3 ms | ≥10min: +1 ms
+ Short PMK ageout + deg≥1: +5 ms
+ Stale PMK cache + deg≥1: +3 ms
+ MAC-DoS OFF + cred storm: +3 ms
+ IP-DoS OFF + ARP attack: +3 ms

lat = max(2, round(lat))
At u=0.36 (golden-set 100/100 state): qd = 6×0.36/(1−0.36) = 3.4ms, lat = 8+3.4 = 11ms before subtracting TXOP VO = 4ms → ~7ms aggregate. POS sees 0.12× of this via rTWT.

9 · POS Latency — rTWT Hardware Scheduling

Restricted Target Wake Time latency guarantee
/* rTWT ON + AP has MLO (AP5060) */
posLat = max(1, min( b5.lat × 0.12, 3 )) /* 8× reduction, capped at 3ms */

/* rTWT OFF */
posLat = b5.lat /* POS shares same queue as all traffic */

/* rTWT OFF + TXOP_BE = 3008µs */
posLat += 1 /* AC_BE TXOP can briefly block AC_VO */
The 0.12× factor models the rTWT service period: POS terminals are pre-scheduled into a dedicated 1.2% of airtime window. At b5.lat=12ms → posLat = max(1, min(1.44, 3)) = 1.4ms. At golden set: posLat ≈ 1.6ms.

10 · Packet Loss Model

Combined airtime saturation + SNR loss
airLoss = max(0, (min(150, round(u×100)) − 85) × 0.5 )
snrLoss = mcs < 0 ? 50 : mcs < 2 ? 3 : 0

ploss = airLoss + snrLoss /* displayed as % */
airLoss only activates above 85% airtime. At 36% airtime: airLoss = 0. At 90% airtime: airLoss = (90−85)×0.5 = 2.5%. snrLoss fires when MCS drops below 2 (link budget failure).

11 · Goodput per Client

Available throughput per associated client (Mbps)
gp = max(0, effCap × (1−u) / clients )
This is the C3 fix from Sprint 1: gp now uses effCap in both numerator and denominator (consistent with u = demand/effCap). Using raw phyR in the numerator would over-estimate available throughput by 2× at golden-set settings.

12 · MLO Combined Throughput (AP5060 only)

Multi-Link Operation — simultaneous 5GHz + 6GHz
MLO_GAIN = { STR: 1.90, Enhanced: 1.55, NSTR: 1.20 }
triLink = (mloLinks===3 && b2 active) ? 1.12 : 1.0 /* 3rd link +12% */

mlo.tput = round( (b5.gp + b6.gp) × MLO_GAIN[mode] × 0.85 × triLink )
mlo.lat = min(b5.lat, b6.lat)
mlo.gain = mlo.tput / max(b5.gp, b6.gp)
The 0.85 factor is an overhead reservation: STR requires coordination frames between links, consuming ~15% of combined capacity. At golden set (STR, 2-link): mlo.tput ≈ 234 Mbps displayed in the MLO card.

13 · Stadium-Wide Capacity and Demand

Aggregate across all APs
capGbps = ( sum of band.effCap for each active band ) / 1000 × apCount
demGbps = active × demTot / 1000

14 · QoE Score (0–100)

Composite quality score with deduction rules
score = 100

SNR deduction: SNR < 25 dB → −min(20, (25−SNR) × 1.2)
Airtime deduction: air > 70% → −min(25, (air−70) × 1.0)
Latency deduction: lat > 20ms → −min(20, (lat−20) × 0.4)
Loss deduction: ploss > 0.1% → −min(20, ploss × 10)
Degradation: deg > 0 → −deg × 12
Cyber active: → −8
PMF OFF + deauth: → −10 (additive on top of −8)

score = max(0, round(score))

STABLE badge:
score ≥ 80 → STABLE (green)
score ≥ 60 → WARNING (yellow)
score < 60 → CRITICAL (red)
At golden-set, 100/100 screenshot: SNR ~38 dB (no deduction), air = 36% (no deduction), lat = 7ms (no deduction), ploss = 0% (no deduction), deg = 0, cyber = none → score = 100.

15 · SLA Pass / Fail Criteria

Service class thresholds
POS PASS : posLat ≤ 10ms AND ploss < 0.3%
VIP PASS : bestTP ≥ 25 Mbps
Teams PASS : bestTP ≥ 5 Mbps
Guest PASS : score ≥ 50
bestTP = mlo.tput when MLO is active; otherwise gp of the best available band (6G > 5G > 2.4G).

16 · Cyber Attack Effects on 5GHz Band

Airtime and latency penalties by threat type
deauth: air += PMF ON ? 1 : 15 | lat += PMF ON ? 0 : 8
evil_twin: air += AirDef ON ? 0 : 5 | lat += AirDef ON ? 0 : 3
cred_storm: air += 0 | lat += 6
ARP poison: air += ProxyARP ON ? 0 : 6 | lat += ProxyARP ON ? 0 : 4

Bug Fix Log — Sprint 2 Debug Trail

Bug Fix 1 · Commit 906c0d5

Optimizer was resetting cyber / degradation to zero

Symptom: "When I apply the optimized knobs why does my cyber attack and other degradations go down to zero?"

Root cause: applyOptResult() called applyOptimal() which hard-sets deg-lvl = 0 and cyber = none. The optimizer was supposed to only touch the 12 search-space knobs.

Fix: Removed the applyOptimal() call from applyOptResult(). The function now only iterates over the 12 knob→elementId mapping and calls update(). Cyber and degradation are preserved.

Why it matters: The whole point of "Apply Optimized Knobs" is to tune the radio parameters within a degraded or threatened scenario, not to pretend the scenario doesn't exist.

Bug Fix 2 · Commit 9159032

Full Config modal silently did nothing — TDZ crash

Symptom: Clicking Full Config button produced no visible modal. No error in UI.

Root cause: JavaScript Temporal Dead Zone (TDZ). const OPT = {...} was declared at line 1260 inside showCfg() but referenced at line 1233 inside an Object.entries(OPT_SEARCH).forEach() loop. In JavaScript, const is hoisted but not initialized — accessing it before its declaration line throws ReferenceError: Cannot access 'OPT' before initialization, even inside a typeof check. Because there was no try/catch, the modal never rendered.

Fix: Moved const OPT to the top of showCfg(), before all references. Added a try/catch wrapper around the entire function body so future errors surface in the log bar instead of failing silently.

Bug Fix 3 · Commit 9159032

MC percentile hardcoded — user wanted free input

Symptom: "In MonteCarlo, why is it hard coded to P50/P75 or P99, can you not take the user-input here?"

Fix: Added a number input id="mc-pct-custom" alongside the dropdown. The getMCPct() helper reads the custom field first; if it holds a valid integer 1–99, it overrides the dropdown. If empty or out of range, the dropdown value is used.

Self-referential bug during fix: A replace_all on the pattern +(g('mc-pct')||{value:50}).value accidentally replaced the pattern inside the helper's own body, creating infinite recursion. Resolved by rewriting the function without the problematic pattern.

Bug Fix 4 · Commit 9f935ff

Full Config crash — curFmt.padEnd is not a function

Symptom: Log bar showed: Full Config error: curFmt.padEnd is not a function. (In 'curFmt.padEnd(18)', 'curFmt.padEnd' is undefined)

Root cause: In the SECTIONS forEach loop, some parameters use fmt: v => v (identity function). When v is a number (e.g., dtim = 2), the returned curFmt is a JavaScript number — and numbers have no .padEnd() method.

Fix: Wrapped with String(curFmt).padEnd(18) and String(optFmt) throughout the comparison row builder. Numbers are now coerced to strings before any string method call.

Bug Fix 5 · Commit 4070855

SLA panel would not scroll — 4 failed attempts

Symptom: The panel below the SLA inputs was not scrollable. Four prior fixes failed.

Root cause (discovered on 5th attempt): resize: vertical requires a fixed height to work. All prior attempts used min-height, max-height, or height values that happened to be large enough to contain the ~125px content. The key insight: content must actually overflow the container for a scroll handle to appear. The container's parent .panel is a block container (not flex), so resize: vertical is respected — previous failures were purely a height arithmetic issue.

Fix: height: 80px; overflow-y: scroll; resize: vertical; min-height: 60px; box-sizing: border-box. At 80px, the ~125px content overflows by 45px. overflow-y: scroll (not auto) always shows the scrollbar handle. The browser drag handle is on the bottom-right corner.

Design Decision

Why rule-based, not optimizer-driven

Cyber threats and physical jammers require deterministic countermeasures, not a gradient search. PMF must be ON to stop deauths — there is no "maybe PMF" tradeoff to optimize. The rule engine makes the causal chain explicit: parameter → mechanism → effect. This also teaches the user the WiFi security reasoning, not just the correct knob value.

Future Sprint 3+: integrate threat context as a constraint into the optimizer so that the 12-knob search space adapts to the active threat archetype.
