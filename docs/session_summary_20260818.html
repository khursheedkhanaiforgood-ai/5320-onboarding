The VLAN 154 Problem

Every approach to add VLAN 154 to port 1/5 was blocked by Auto-Sense. The switch enforces a conflict between manual VLAN assignment and Auto-Sense port ownership.

Attempts Made

Command TriedResult

Circular Conflict Adding VLAN 154 manually → Auto-Sense disables → VLAN 153 (management) drops → CAPWAP at risk. Restoring VLAN 153 → Auto-Sense re-enables → VLAN 154 removed. Every CLI path cascades into breaking something else. The global wap-type1 Auto-Sense profile supports only ONE I-SID.

Why ASGN AUTH = none on port 1/5 AP_NPS was factory-reset today. The factory reset wiped the FA message authentication key that Karl's XIQ policy originally configured. EP1 (Khursheed's instance) has no FA/I-SID configuration to push — EP1 does not expose Auto-Sense/FA settings. Therefore AP_NPS is not advertising I-SID 144154 to the switch, and the switch has nothing to dynamically assign. This is NOT a port issue — it is a device + policy gap.

Why EP1 Cannot Fix This

EP1 (Extreme Platform One) has no Fabric Attach or I-SID configuration section for APs. The FA message authentication key and I-SID bindings are pushed exclusively through Karl's XIQ SwitchEngine template to KhKLab-SW-01. The AP cannot advertise I-SID 144154 without this being configured either in the switch template or directly on the AP.

Root Cause Summary

Primary — Switch Template Gap Karl's XIQ switch template for KhKLab-SW-01 configures the wap-type1 Auto-Sense FA profile with only I-SID 144153 (VLAN 153, AP management). I-SID 144154 (VLAN 154, WirelessUser — 802.1X data VLAN) is not in the profile. Auto-Sense therefore never assigns VLAN 154 to any AP uplink port.
Secondary — FA Auth Key Lost After Factory Reset AP_NPS factory reset wiped the FA message authentication key. Karl's XIQ policy needs to re-push it. Until then, ASGN AUTH = none for port 1/5. This prevents FA from dynamically assigning VLANs even if the profile were updated.
Everything Else is Working 802.1X auth (RADIUS/NPS), EP1 classification (TVG → VLAN 154), AP tagging (eth0 VLAN 154), VOSS switch management path (VLAN 153, CAPWAP), DHCP server on VOSS (10.154.4.0/24 pool configured) — all confirmed ready. One switch template update from end-to-end success.
