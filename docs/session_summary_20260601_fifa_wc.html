Policy_Guest is the catch-all — must be last. Any user not matched by policies 1–4 lands here on VLAN 30.

RADIUS Attribute

EP1 Security returns Attribute 11 — Filter-Id with the policy name as the value (e.g., Policy_TeamUSA). It does NOT return Tunnel-Type/Tunnel-Medium/Tunnel-PVT-Group-ID directly. EP1 Core maps the Filter-Id string to a VLAN via assignment rules.

RadSec Proxy — Critical Finding

A RadSec Proxy (Local Survivability) entry was present in EP1 Security → Security Services → RADIUS. This proxy intercepted all authentication requests and returned: "local survivability is enabled but cloud support is not enabled for local user." All authentications failed until this proxy was deleted. Do not re-add unless intentionally configuring local survivability.

6. Blockers & Root Cause Analysis

Primary Blocker — macOS EAP-TTLS/PAP

Root cause: Apple removed EAP-TTLS/PAP inner authentication from the macOS and iOS UI starting with Ventura (macOS 13) and iOS 17. The protocol still works over 802.1X — but only when forced via a signed MDM/mobileconfig profile. An unsigned profile installs but requires explicit user trust under System Settings → General → VPN & Device Management before it activates.

Impact: Cannot manually join WPA3-Enterprise with EAP-TTLS/PAP on any modern Apple device without a mobileconfig. The mobileconfig approach requires either MDM signing or manual trust activation.

Why EAP-TTLS Was Chosen (and Why It Created Problems)

EP1 Security local accounts use password-based auth. The supported EAP methods for password auth are EAP-TTLS and PEAP. PEAP-MSCHAPv2 requires an Active Directory backend — EP1 Security local accounts do not support it. EAP-TTLS/PAP was the only viable path for local user auth. Had this constraint been flagged earlier, the lab would have been designed around Android or Windows clients from the start.
