Context

This document captures the Supplemental CLI block pushed to 5320_voss_mylab (nick-name 0.00.01) via XIQ Advanced Settings → Supplemental CLI after OS conversion from EXOS to VOSS. The peer switch is 5320_voss_se (KhKLab-SW-01, nick-name 0.00.02), running VOSS 9.3.2.0, pre-flight dumped and verified Aug 21 2026.

I-SID Namespace Clear Pre-flight on 5320_voss_se confirmed I-SIDs 10010 and 10020 are not in use. Karl's switch uses 144153–144156, 15999999, 16777001. MyLab namespace is safe.
Two Bugs Caught and Corrected (1) Auto-sense syntax: earlier drafts had auto-sense i-sid data 10010 — wrong keyword order. Correct syntax confirmed from Karl's running config: auto-sense data i-sid 10010.

(2) B-VID missing: spbm 1 b-vid 4051 primary 4051 was absent from Group 2. XIQ ZTD may assign different B-VIDs on a fresh VOSS deploy — without this line explicitly matching Karl's 4051-4052, IS-IS adjacency forms but SPBM fabric does not.
DNS Missing from DHCP Pool — Discovered Aug 21 2026 Group 7 (DHCP Server) was missing ip dhcp-server domain-name-servers 8.8.8.8 8.8.4.4. A fresh AP received an IP and gateway but could not resolve oh-cwm.extremecloudiq.com — CAPWAP stayed in DISCOVERY with no visible error on the switch. Added as Group 11. Run this before saving config on any new VOSS deploy.
A-Priori VLAN → I-SID Convention I-SID = VLAN + 10000. VLAN 10 (Staff) → I-SID 10010. VLAN 20 (Guest) → I-SID 10020. This mapping is hard-coded on every switch — the AP never needs to know the I-SID number.

CLI Command Groups

# Group CLI Commands What It Does
1 IS-IS Identity 
router isis
  sys-name "KhKLab-SW-02"
  is-type l1
  ip-source-address 10.0.0.1
exit
 Names the switch in the IS-IS topology. is-type l1 = Level 1 only, matching Karl's switch. The source address is the loopback — this is what other BEBs use to reach this switch via fabric IP shortcuts. Must match the loopback interface created in Group 6.
2 SPBM Instance 
spbm 1 nick-name 0.00.01
spbm 1 b-vid 4051 primary 4051
spbm 1 multicast enable
spbm 1 ip enable
router isis enable
 Defines SPBM instance 1. Nick-name 0.00.01 uniquely identifies this BEB in the fabric — Karl's is 0.00.02, must not collide. b-vid 4051 primary 4051 explicitly sets B-VLANs to match Karl's switch — XIQ ZTD may assign different defaults on a fresh deploy, so this must be hardcoded. ip enable = fabric carries IP shortcuts between BEBs. multicast enable = SPBM multicast forwarding active.
3 Area Membership 
manual-area 49.b0b1
 Joins this switch to IS-IS area 49.b0b1. Karl's switch learned this dynamically from a neighbor — this switch declares it explicitly. Both sides must be in the same area for IS-IS adjacency to form. If adjacency fails, verify this matches on both ends.
4 VLAN + I-SID Binding 
vlan create 10,20 type port-mstprstp 0
vlan i-sid 10 10010
vlan i-sid 20 10020
vlan name 10 Staff
vlan name 20 Guest
 Creates service VLANs and hard-codes the a-priori binding. vlan i-sid 10 10010 is the single line that makes the architect's intent real — once it exists, the fabric knows VLAN 10 = I-SID 10010 on every switch. Every other BEB that sees I-SID 10010 in the LSDB treats it as Staff. The AP only needs to tag with VLAN 10; the switch resolves to 10010 automatically.
5 Anycast Gateway SVIs 
interface Vlan 10
  ip address 10.0.10.1 255.255.255.0 2
exit
interface Vlan 20
  ip address 10.0.20.1 255.255.255.0 3
exit
 Creates the L3 gateway for each VLAN on this BEB. Clients on VLAN 10/20 use these as their default gateway. Architecture lever: presence of both SVIs = cross-VLAN routing is possible. Remove one SVI = that I-SID becomes an isolated L2 bubble. No ACL needed for isolation — it's structurally absent.
6 Loopback (IS-IS Source) 
interface loopback 1
  ip address 1 10.0.0.1/255.255.255.255
exit
 Creates the loopback that IS-IS uses as its source address. Must match ip-source-address 10.0.0.1 in Group 1. Without this interface, IS-IS may not start or will use a suboptimal source. Karl's equivalent: loopback 10.159.4.1/32, CLIP 10.158.4.1/32.
7 DHCP Server 
ip dhcp-server subnet 10.0.10.0/24
pool 10.0.10.100 10.0.10.200
router 10.0.10.1
lease-time 86400
exit
ip dhcp-server subnet 10.0.20.0/24
pool 10.0.20.100 10.0.20.200
router 10.0.20.1
lease-time 86400
exit
ip dhcp-server enable
 Local DHCP for Staff and Guest clients. This switch serves addresses directly — no relay needed for first-pass test. Karl's switch uses relay (fwd-path to CLIP) because his DHCP server is centralised. For mylab, local server is simpler and self-contained.
8 Auto-Sense / FA 
auto-sense data i-sid 10010
auto-sense fa wap-type1 i-sid 10010
 Tells auto-sense what to do when an FA-capable AP connects. wap-type1 = FA AP profile (AP3000). Switch advertises I-SID 10010 to the AP via FA TLVs over LLDP. AP uses this to tag its management traffic into the fabric. Syntax confirmed from Karl's running config — keyword order matters.
9 Route Redistribution 
router isis
  redistribute direct
  redistribute direct enable
exit
isis apply redistribute direct
 Injects directly connected subnets (VLANs 10/20, loopback) into IS-IS so Karl's switch can reach them via fabric IP shortcuts. Without this, only L2 fabric works — routed reachability between BEBs is absent. The isis apply line activates the redistribution immediately without a reboot.
10 Management + Default Route 
interface vlan 1
  ip address 192.168.0.29 255.255.255.0 1
exit
ip route 0.0.0.0/0 192.168.0.1 weight 1 enable
 In-band management IP on VLAN 1 — use 192.168.0.29 to avoid conflict with Karl's switch on the home LAN. Default route via modem (192.168.0.1) for internet reachability. Verify .29 is free on your subnet before pushing. DHCP must not be serving this address from another device.
11 DNS for DHCP 
ip dhcp-server domain-name-servers 8.8.8.8 8.8.4.4
 The missing piece. Without this, a fresh AP gets a DHCP address and a gateway but cannot resolve oh-cwm.extremecloudiq.com — CAPWAP stays in DISCOVERY forever with no visible error. This is a global DHCP server command (not per-subnet), so it applies to both VLAN 10 and VLAN 20 pools simultaneously. Identified after observing AP stuck at ip route 192.168.0.0/16 on mgt0 with no default route because DNS lookup returned nothing.
12 Persist 
save config
 Writes everything to flash. Without this, a reboot wipes all groups above. Run this last, after verifying IS-IS adjacency forms and AP registers correctly.

Debug Sequence

If something breaks post-deployment, walk these groups in order — each group is a layer of the stack:

  1. Group 3 — Area: show isis → is manual-area 49.b0b1 present and adjacency forming?
  2. Group 2 — SPBM: show isis spbm → is nick-name 0.00.01 visible? Is ORIGIN static (not dynamic)?
  3. Group 4 — I-SIDs: show vlan i-sid → are 10010/10020 bound correctly?
  4. Group 8 — FA: show fa or show auto-sense → is AP sending FA TLVs and getting I-SID 10010?
  5. Group 9 — Routing: show isis lsdb → are 10.0.10.0/24 and 10.0.20.0/24 visible in Karl's LSDB?
  6. Group 10 — Reachability: Can you SSH to 192.168.0.29? Does ping 192.168.0.1 succeed from the switch?
  7. Group 11 — DNS: From a DHCP client, run nslookup oh-cwm.extremecloudiq.com or from the AP CLI: does capwap show client show DTLS Connected within ~60s? If still DISCOVERY, DNS is the first suspect.
