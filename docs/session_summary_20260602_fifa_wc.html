§2 — Simulator v2 Phase 1 Architecture

The v1 simulator was a single-band, fixed-demand model with one airtime pool. Phase 1 of v2 rebuilds it from scratch as a full multi-band WiFi 7 simulator. Every parameter that the Extreme EP1 radio profile and SSID optional settings expose is now tunable in one panel.

Design Principle — Phase 1

Phase 1 is deterministic. All clients have fixed per-app demand rates. The simulator asks: given these exact settings, what is the QoE? Phase 2 (not yet built) will introduce stochastic arrivals — Poisson client sessions, Pareto-distributed per-client demand, and burstiness variance. Phase 1 is the foundation.

§3 — Qualcomm IPQ9574 Chip Parameters

The user provided the full CLI export from the WiFi 7 AP Design Tool for the Qualcomm IPQ9574 chipset (AP5010). This is the silicon inside the AP5060. The export contained 27 parameters. Seven were not yet in the Phase 1 simulator and were integrated in commit 360d43e.

The Seven New Parameters — Model and Effect

EDCA CWmin AC_BE
15 slots (IPQ9574)
Min contention window for best-effort. CW=7 → 3× more collisions when airtime >70%. Modelled: +3ms latency penalty at CW=7 & u>0.7.
WMM TXOP AC_BE
3008 µs (IPQ9574)
Best-effort burst duration. Higher = better bulk tput. Risk: when rTWT OFF, a 3008µs BE burst can briefly starve AC_VO. Modelled: ×1.05 capacity + +1ms POS latency when rTWT=OFF.
RTS/CTS Threshold
1500 B (IPQ9574)
Frames above threshold trigger RTS/CTS handshake → mitigates hidden terminal collisions in dense 280-AP stadium. Modelled: ×1.04 capacity multiplier.
MU-MIMO DL Streams
8 streams (IPQ9574)
IPQ9574 supports 8-stream DL MU-MIMO (serves 8 clients simultaneously). Sublinear gain model: {1:×1.0, 2:×1.3, 4:×2.0, 8:×2.8}. AP3000 capped at ×1.6 (2SS hardware).
4K-QAM (MCS 12/13)
Enabled at SNR≥42dB
When OFF: MCS capped at 11 (WiFi 6 ceiling). When ON: MCS12 at SNR≥42dB, MCS13 at SNR≥46dB. Only for WiFi 7 EHT (AP5060, gen=ʻbeʼ). PHY rate jumps: MCS11→MCS13 is +25% at 320MHz 4SS.
MLO Active Links
2 links — 5G + 6G
1 link = MLO disabled entirely. 2 links = current STR 5G+6G bonding. 3 links = tri-band 2.4+5+6G (+12% gain from 2.4G channel addition). IPQ9574 ships as 2-link STR.
MLO Traffic Steering
AI-driven (EP1 RRM)
WMM-QoS = standard per-AC priority steering. AI-driven = EP1 RRM continuously re-balances per-link load in real time. Modelled: ×1.04 capacity multiplier vs WMM-only.

§4 — PPSK Self-Registration Flow

The goal: a fan arrives at Lumen Field, has no passphrase, and wants to get onto WC_Seattle-PPSK (the per-user passphrase SSID that puts them on their assigned VLAN). This requires a self-service registration pathway that EP1 can handle entirely without a help desk.

Two-SSID Architecture

Architecture Decision

A single SSID cannot serve as both the landing zone (no password needed) and the target SSID (PPSK-protected). Two SSIDs are required: one Open for the CWP landing, one PPSK for the final connection. EP1 CWP bridges them.

  1. Fan's device connects to WC_Guest_CWP — Enhanced Open (OWE), no password required
  2. EP1 CWP intercepts the HTTP request and serves the self-registration form (name + email)
  3. EP1 generates a unique PPSK passphrase and assigns it to the submitted email as a new user
  4. EP1 emails the passphrase + QR code to the fan's email address — no customer SMTP needed (EP1 cloud infrastructure handles delivery)
  5. Fan opens email, scans QR code → device auto-connects to WC_Seattle-PPSK with the passphrase
  6. PPSK auth → EP1 Core evaluates user group → assigns VLAN 30 (Guest) via dynamic VLAN profile

QR Code Format

WIFI:T:WPA;S:WC_Seattle-PPSK;P:<generated_passphrase>;;

Standard Wi-Fi QR code format — compatible with iOS Camera app and Android native scanner. No app install required. Fan scans, device joins automatically.

EP1 Config Location

The PPSK generation, email delivery, and QR code settings all live inside the CWP profile → email/notification tab. No separate email server or webhook is needed. EP1's cloud infrastructure handles the outbound email on behalf of the customer.

Security note: The landing SSID WC_Guest_CWP is Enhanced Open (OWE) — traffic is encrypted in transit even without a password. The PPSK SSID WC_Seattle-PPSK uses WPA2-PSK with per-user passphrases. Once a fan has their passphrase they always connect to the PPSK SSID, never returning to the CWP landing SSID.

Critical Lesson — CWP Profile Type

CWP profile type must match SSID auth type exactly

Attempting to attach a standard Open CWP profile to an Enhanced Open SSID causes a save error in EP1. You must create a new CWP profile with type set to Enhanced Open. The error is cryptic — "profile type mismatch" — but the fix is straightforward: create a dedicated CWP profile for the OWE SSID.

EP1 Cloud Email — No SMTP Required

EP1 is a cloud-hosted platform. The CWP self-registration email (welcome email, passphrase delivery, QR code) is sent by EP1's cloud infrastructure directly. The customer does not need to configure an SMTP relay, an email server, or any outbound mail credentials. This is a significant operational simplification for a temporary event like a FIFA World Cup venue.

§7 — Key Learnings

Lesson 1 — Simulator Design

Reset to Worst Case, not Baseline

The ↺ Reset button sets every parameter to its worst possible value (all features OFF, MBR=12, CW=63, etc.), not a "reasonable baseline." This is pedagogically superior: the full delta from worst to optimal is visible in one click. Each gap row in the Gap Analysis tab directly links to a specific parameter the user can then fix. The score typically goes from ~12/100 (worst case) to ~96/100 (Stadium Optimal).

Lesson 2 — Airtime Fairness Is the Biggest Lever

1 MCS0 device consumes 32× the airtime of an MCS11 device

In a 72,000-fan stadium with thousands of older phones, Airtime Fairness is not optional. Without it (AF=OFF), a handful of devices with bad RF can steal the entire airtime budget. With Strict AF the aggregate throughput improves by ×1.38. No other single parameter has this magnitude of effect in a dense public venue.

Lesson 3 — IPQ9574 CWmin Models at High Load

CWmin AC_BE = 7 causes collision storms above 70% airtime

The contention window minimum sets how quickly a device retries after a collision. At low load, CW=7 is fine — retries happen fast and succeed. At high load (airtime >70%), many devices are retrying simultaneously. CW=7 means they all retry almost simultaneously → exponential collision cascade. IPQ9574 uses CW=15 as the sweet spot: fast enough for throughput, large enough to spread retries.

Lesson 4 — CWP Profile Type Must Match SSID Auth

Enhanced Open SSID requires Enhanced Open CWP — not standard Open

EP1 enforces a strict type match between the SSID authentication type and the CWP profile type attached to it. An OWE (Enhanced Open) SSID will reject a standard Open CWP profile at save time. The error message in EP1 says "profile type mismatch." Fix: create a new CWP profile with auth type explicitly set to Enhanced Open.

Lesson 5 — EP1 Email Delivery Needs No SMTP

CWP self-registration email is sent by EP1's cloud infrastructure

Customers deploying EP1 CWP with email delivery (welcome email, passphrase QR code) do not need to configure outbound mail. EP1 handles SMTP through its own cloud infrastructure. This is a significant operational simplification: no email server provisioning, no SPF/DKIM records, no SMTP relay firewall rules needed at the venue.

Lesson 6 — Phase 1 vs Phase 2 Simulator

Deterministic now, stochastic later

Phase 1 assumes all clients have identical per-app demand at all times — it is a steady-state capacity model. Phase 2 will introduce Poisson arrival rates for client sessions, Pareto-distributed per-client demand (heavy tail — a small fraction of clients consume most bandwidth), and burstiness variance. Phase 1 is sufficient for parameter tuning and breaking-point discovery. Phase 2 is needed for realistic traffic simulation.
