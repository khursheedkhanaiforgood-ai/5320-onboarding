AP1 Show Tech — Key Lessons

Source: device_support_logs_2026-Jun-15-16_57_08/core_dump41/show_tech_result.txt

1. Reboot Pattern — Config Rollback Loop

3 reboots on June 10 (15:41, 15:59, 16:11) plus multiple on May 20-21. Root cause: config rollback is enabled. When EP1 pushes a policy and the CAPWAP session drops mid-push, the AP rolls back to prior config and reboots. Short DHCP lease (3600s) on the management IP exacerbates this — lease expiry during an EP1 push causes CAPWAP drop → rollback → reboot cycle.

2. RadSec SSL Timeouts

Recurring SSL read timeouts to oh-idmauth.extremecloudiq.com on May 20, June 9, June 10, and June 15 overnight. When the TLS session to the RadSec proxy drops, PPSK authentication fails for all clients — the AP cannot validate credentials without cloud connectivity.

3. Walled-Garden DNS Slow

Guest CWP (Captive Web Portal) shows slow DNS responses for the walled-garden domain list. Manifests as delayed redirect when guests first connect — portal takes 5-10s to appear instead of immediate.

4. DHCP Lease Too Short

AP management IP (192.168.0.12) has a 3600s (1hr) lease from QF_Modem. On lease renewal failure, the AP loses its management IP → CAPWAP session drops → config rollback → reboot. Fix: set DHCP static reservation + extend lease to 86400s (24hr) on QF_Modem.

5. Location-Essentials Load

Location-Essentials enabled → hundreds of Locn-essential CAPWAP events per minute. Normal behavior but contributes to AP CPU load and CAPWAP session traffic volume. Console login failures on June 10 were our own serial session (backspace escape characters appearing in log — not an intrusion).

Roaming Hops + Client Speed

Roaming hops controls how far the PMK cache pre-propagates to neighboring APs. It is indirectly tied to client mobility speed:

  • 1 hop: PMK shared only with directly adjacent APs. Fast walkers who skip a neighbor and land on a non-adjacent AP hit full re-auth → 200-500ms gap → VoIP drop.
  • 2 hops: Cache pre-positioned one level further. Covers normal office walking pace. Confirmed setting for this lab.
  • 3 hops: For high-mobility environments — carts, forklifts, jogging.

Three-Way Alignment Required

All three must match or the shortest timer becomes the failure point:

  • DHCP lease time (QF_Modem) → 86400s
  • PMK max caching time (EP1 roaming settings) → 86400s
  • Roaming cache max caching time (AP roaming profile) → 86400s

Currently all three at 3600s — a 1-hour lease expiry on the AP management IP cascades into CAPWAP drop → config rollback → reboot.

EP1 Priority Actions

Five changes to make in EP1 — in priority order:
  1. Disable ADSP on radio profiles (5G_Khursheed_80MHz + radio_ng_11ax-2g) → unblocks pcap capture on wifi0 and wifi1
  2. Raise basic rate to 12 Mbps on both SSIDs → reduces stickiness, improves VoIP handoff, nudges edge clients toward 5GHz
  3. PMK max caching time → 86400s (24hr) → aligns with DHCP lease
  4. Roaming hops → 2 (confirmed) → PMK cache pre-propagates one level further for fast walkers
  5. QF_Modem: DHCP static reservation + 24hr lease for 192.168.0.12 → eliminates management IP expiry reboot cycle

XE Socratic Scenarios — June 15

8 scenarios completed using Karl Scenario Socratic method: brief situation, user asks questions, terse answers, user reaches root cause independently.

XE-11 Orange

wifi0 CRC Errors Spike to 45% — Neighbor Company Moved In

wifi0 (2.4GHz) CRC jumped from <5% to 45%. wifi1 (5GHz) clean at 3%. Another company moved into shared office last month. Root cause: 2.4GHz interference from neighbor's WiFi raised the noise floor — CRC climbs, MCS drops, edge clients degrade or disconnect.

Fix: raise MBR to 12 Mbps on 2.4GHz, enable band steering to nudge clients to 5GHz, verify 5GHz CU + retry rate + client count has headroom, change to non-overlapping 2.4GHz channel (or enable ACSP).

XE-12 Yellow

AP4000 6GHz Radio — No WiFi 6E Clients Connecting

6GHz SSID visible on analyzer. MacBook M2 and Samsung S23 both connect to 5GHz only. Root cause: same security profile used on 6GHz as 5GHz. 6GHz requires WPA3-SAE only — PPSK is WPA2-based and is incompatible with 6GHz.

Fix: create a separate 6GHz SSID with WPA3 security profile. Note: 5GHz beacons advertise 6GHz BSS via Reduced Neighbor Report (RNR) — clients read RNR to discover 6GHz without scanning all channels.

XE-15 Red

30 APs Simultaneously Drop 5GHz — DFS Channels 100–140

10:47am, 30 AP410Cs simultaneously drop 5GHz radios and begin channel scan. All on DFS channels 100-140. Non-DFS APs (36-64) unaffected. Root cause: TDWR (Terminal Doppler Weather Radar) — operates around 5.6 GHz, overlaps channels 120/124/128. A single radar pulse strong enough to be detected by all 30 APs simultaneously triggered 802.11h channel move events.

Fix: migrate to non-DFS channels 36-64 (UNII-1 + UNII-2a). Or migrate eligible devices to 6GHz. Avoid channels 100-140 if any airport/weather radar within line-of-sight range.

XE-16 Yellow

Band Steering Overcrowds 5GHz — 200-Student Lecture Hall

Band steering enabled on one AP, 200 dual-band laptops, all forced to 5GHz. 5GHz now at 85% CU, 2.4GHz empty. Performance worse than before. Root cause: single AP cannot serve 200 clients on one 5GHz radio — CU saturation kills throughput.

Fix: add more APs, disable or threshold band steering (don't steer past 5GHz CU limit), enable client load balancing across APs. AP-level max client cap per radio is the simplest control.

XE-17 Yellow

TX Power at Max — RSSI Great, Performance Worse

New admin set all 90 APs to max TX power (30 dBm). RSSI everywhere -40 to -55 dBm. CRC up across the board. Users report slower speeds and disconnects. Root cause: co-channel interference — every AP now overpowers adjacent co-channel APs. RSSI is high but SINR collapses. CRC climbs, MCS drops, throughput falls.

Fix: reduce TX power to allow ACSP to assign appropriate power levels, enable ACSP for automatic channel and power optimization. Verify CU, CRC, retry rate after adjustment.

XE-19 Orange

ExtremeControl NAC Quarantine — Random 5% of Students

5% of students randomly quarantined after successful authentication. Same device, same credentials — passes Monday, quarantined Tuesday. Self-service portal releases them until next time. Root cause: posture assessment timeout. NAC agent check (AV, patch level, agent version) doesn't complete within the timeout window — device load or network latency varies — NAC fails closed into quarantine.

Fix: increase posture assessment timeout window, audit what checks are being run (remove non-critical checks), verify ExtremeControl agent is current on affected devices.

XE-20 Yellow

PPSK PCG Enabled — Clients Still Ping Each Other

Hotel deployed PPSK with Private Client Groups for guest isolation. XIQ confirms PCG on. Security auditor pings between two laptops with different PPSK keys — succeeds. Root cause: PCG enforces L2 isolation at the AP level only. Traffic routing through the upstream switch/router in the same subnet is not blocked by PCG — the router forwards L3 traffic between guests regardless of AP-level isolation.

Fix: ACL on upstream firewall/router blocking intra-VLAN client-to-client traffic. PCG = L2 enforcement at AP; firewall = L3 enforcement past the AP. Both layers needed for true guest isolation.

XE-21 Red

800 PPSK Keys Expire at Midnight — Product Launch Tomorrow

4pm discovery: all 800 PPSK credentials in one XIQ user group expire tonight at 11:59pm. Overnight lab session + 800-person product launch at 8am tomorrow. No bulk renewal visible in UI. Root cause: all credentials set with same expiry date 12 months ago when program was configured.

Fix: edit expiry date on the user group before midnight, push policy update to all APs. Lesson: never configure all credentials with the same expiry date — stagger expiry across user groups. Always maintain a renewal playbook.

Karl Scenario Style — Adopted

For all future scenario sessions: brief situation statement, user asks all questions, one-word or one-sentence answers only, no hints unless user is stuck, no volunteered information. User reaches root cause independently through questioning. This is the method used by Karl Benedict in real customer escalations.
