DHCP Syntax Debug — Three Wrong Turns

Wrong Syntax #1 — Named Range Objects (Invalid) create dhcp-address-range Staff-Range ipaddress 10.10.10.100-10.10.10.200
EXOS does not use named DHCP range objects. This command does not exist in SwitchEngine 33.x.
Wrong Syntax #2 — DHCP Client Command enable dhcp vlan Staff
This enables the DHCP client on that VLAN (switch requests an IP from upstream). Rejected with error: "Can't enable BOOTP/DHCP client, as an IP address is configured."
Wrong Syntax #3 — DHCP Server Per Port enable dhcp ports 3 vlan Staff
External AI source said this enables DHCP client on port 3 — incorrect. EXOS ? help confirmed: ports = "Specify port(s) to configure DHCP server for." This IS the correct server activation.
Correct DHCP Syntax — Verified on EXOS SwitchEngine 33.x 
# Per-VLAN DHCP server configuration (spaces around hyphen required):
configure vlan Staff dhcp-address-range 10.10.10.100 - 10.10.10.200
configure vlan Staff dhcp-options default-gateway 10.10.10.1
configure vlan Staff dhcp-options dns-server primary 8.8.8.8
configure vlan Staff dhcp-options dns-server secondary 8.8.4.4
enable dhcp ports 3 vlan Staff

configure vlan Students dhcp-address-range 10.20.20.100 - 10.20.20.200
configure vlan Students dhcp-options default-gateway 10.20.20.1
configure vlan Students dhcp-options dns-server primary 8.8.8.8
configure vlan Students dhcp-options dns-server secondary 8.8.4.4
enable dhcp ports 3 vlan Students

configure vlan Devices dhcp-address-range 10.30.30.100 - 10.30.30.200
configure vlan Devices dhcp-options default-gateway 10.30.30.1
configure vlan Devices dhcp-options dns-server primary 8.8.8.8
configure vlan Devices dhcp-options dns-server secondary 8.8.4.4
enable dhcp ports 3 vlan Devices

configure vlan Guests dhcp-address-range 10.100.100.100 - 10.100.100.200
configure vlan Guests dhcp-options default-gateway 10.100.100.1
configure vlan Guests dhcp-options dns-server primary 8.8.8.8
configure vlan Guests dhcp-options dns-server secondary 8.8.4.4
enable dhcp ports 3 vlan Guests

save configuration
Critical DHCP Distinction enable dhcp ports X vlan Y = DHCP server active on port X for VLAN Y ← correct
enable dhcp vlan Y = DHCP client on VLAN Y ← wrong for this use case

Modem Routing Issue — Solved

Symptom

All 4 VLANs getting correct DHCP IPs. EXOS could ping 8.8.8.8 from its own management IP (192.168.0.28). But clients on 10.x.x.x could not reach internet. AP could not ping 10.100.100.1 (Guests gateway).

Root Cause

CenturyLink modem had no route back to 10.x.x.x subnets. Client traffic from 10.x.x.x reached the modem, the modem forwarded it to internet, but return traffic had no route back from the modem to EXOS → dropped.

Fix

Added static route on CenturyLink modem admin page:

Destination: 10.0.0.0/8
Gateway:     192.168.0.28    (EXOS_PPSK Default VLAN IP)

Modem needed time to apply/refresh the route after saving. Once active, all 10.x.x.x VLAN clients confirmed internet access.

Why 10.0.0.0/8 Covers all four lab subnets (10.10.10.x, 10.20.20.x, 10.30.30.x, 10.100.100.x) in a single route. More specific /24 routes per VLAN would also work but require four entries. The /8 is the cleaner lab choice.

AP/Switch Cloud Architecture — Clarified

ServiceAP_PPSKEXOS_PPSK
OSIQ EngineSwitchEngine (EXOS)
Cloud agentCAPWAP clientIQAgent (software daemon)
Config push from EP1CAPWAP UDP 5246/5247HTTPS TCP 443
Telemetry / MIB to XIQHTTPS TCP 443HTTPS TCP 443
PPSK authenticationRadSec TCP 2083N/A
Time syncNTP UDP 123NTP UDP 123
DirectionAP calls home (outbound)EXOS calls home (outbound)

Key insight: EXOS_PPSK simultaneously plays two independent roles — it is a managed device (IQAgent reports to XIQ, receives config from EP1) AND a router (transparently forwarding AP_PPSK's CAPWAP and RadSec traffic to the cloud). Neither connection depends on the other.

IQAgent is not the OS and not a protocol — it is a software service running on top of SwitchEngine. It translates EP1 policy objects into EXOS CLI commands and reports switch telemetry back to XIQ over the same HTTPS connection.
