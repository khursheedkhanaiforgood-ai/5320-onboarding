PPSK Classification

One SSID, one Network Policy — location-specific keys. The AP's physical location in XIQ hierarchy determines which PPSK key is valid. Store 100's AP only accepts the Store 100 key; a tablet moved to Store 200 is rejected. Requirements: location hierarchy in EP1 > Configuration > Sites; UG DB Location = Local; "Enable use for PPSK Classification only" checked; one PPSK User per location; Classification Rules per location (Device Location match type).

MAC Binding

Locks a PPSK to 1–5 MAC addresses. Local DB only. Designated AP needs static IP (becomes PPSK Server). Unbind options via EP1: by MAC Address, by PPSK key, or by MAC + PPSK (use when multiple devices share one key and you only want to remove one). CLI on AP: show auth mac-binding <SSID-name>.

RadSec (IDM) — The Auth Path

TCP 2083. AP → RadSec Proxy AP → XIQ cloud. IQ_Controller is NOT in this path. Auto-election: 2 proxies per management subnet. Both AP3000s on same EXOS switch = same mgmt subnet = auto-election works (primary + backup). CLI: #show idm is the go/no-go gate before all PPSK config. If output shows "Disconnected" → TCP 2083 is blocked → fix before anything else.

Locked Devices

10 failed PPSK attempts within 7 minutes → device blocked for 30 minutes. EP1 path: Configure > User Management > Locked Users. Checkmark → Unlock → device disappears → can retry. Security measure against DoS attacks on PPSK SSIDs.

Guest Management Role

Delegated admin who sees only the Users page. EP1: Administration & Settings > Access Management > Credential Groups. Scoped to specific User Groups. Guest manager can only create/delete PPSKs they own — XIQ Admin manages all. 2FA with Google Authenticator recommended (HIPAA/PCI contexts). Needs a second non-Extreme email account for lab testing.

Guest Onboarding with CWP

Dual SSID: PPSK SSID (Business-Guest) + Open SSID with CWP (Business-Guest-Onboarding). Guest registers on Open SSID → sponsor gets "Click Approve" email → guest gets PPSK → switches to PPSK SSID.

Single SSID: One Open SSID. Guest registers → stays on same SSID → logs in with PPSK credentials on same CWP page. No SSID switch required.

CWP HTML Hack: Remove sponsor email field from index.html. Add type="hidden" value="sponsor@contoso.com" to hardcode sponsor and hide field from guest UI. First person to click approve link grants access.

Private Client Groups — Full Deep Dive

AP3000 Hardware Reality Check AP3000 = IQ Engine = "supported on all cloud-native access points" per guide p.52. Key-Based PCG may work on AP3000 — verify in EP1 SSID config whether the option can be enabled. AP-Based PCG definitively requires a wall plate AP (AP150W or AP302W) — anchor AP concept requires multiple Ethernet ports and GRE tunneling from room AP. Confirm: do you have a wall plate AP available?

Factory Reset Sequence

Do This First — Before Touching Hardware In XIQ: Delete both AP3000s from their current VIQ. If serial numbers remain registered in old VIQ, APs will auto-reconnect there after reset instead of your test VIQ — and you won't be able to add them to the new one.

AP3000 Factory Reset

# Physical reset (recommended):
# Hold reset pin 10+ seconds → LED flashes rapidly → release
# AP reboots to unconfigured state — takes ~3 minutes

# OR via CLI (if SSH still accessible):
ssh admin@<ap-ip>
reset config

# After reset — MUST clear SSH host key or next SSH connection fails:
ssh-keygen -R <ap-ip>

EXOS Factory Reset

# MUST have console cable connected before running — network access lost immediately
unconfigure switch all
# Confirm: y
# Switch reboots with factory defaults (~2 minutes)
# Default login after reboot: admin / <blank password>
EXOS vs VOSS Reset Commands — Never Swap These EXOS = unconfigure switch all VOSS/FabricEngine = delete /intflash/config.cfg Running the VOSS command on EXOS does nothing useful; running EXOS command on VOSS does not fully reset fabric config.

EP1 Build Sequence for Lab (Do in Order)

  1. Configuration > Sites — Campus-A / Bldg-100 (AP3000-1) + Campus-B / Bldg-200 (AP3000-2). Required before Classification rules can be set.
  2. Monitoring > Network Devices > Device Status > Add Devices — Enter AP serial numbers. Verify CAPWAP Connected state.
  3. Configure > User Management > User Groups — Build all 10 UGs (Staff-BYOD, Students-Cloud, IoT-Devices, Guest-8-Hour, Business-Guest-PPSK, Classification-Bldg100, Classification-Bldg200, PCG-Key-Based, PCG-AP-Based, Guest-CWP).
  4. Configuration > Network Policies — Create 7 scenario policies + all SSIDs.
  5. Configure > User Management > Users — Populate per scenario: single / bulk / CSV / Azure AD sync.
  6. Configure > User Management > Private Client Groups — PCG + Classification config.
  7. Administration & Settings > Access Management — Guest Manager account + Credential Group scoping.
  8. Monitoring > Network Devices > Deploy — Push config to AP3000-1 and AP3000-2.
  9. SSH to each AP: #show idm — Confirm green before testing any PPSK scenario.
