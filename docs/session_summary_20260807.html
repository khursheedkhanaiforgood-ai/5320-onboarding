802.1X Investigation

NPS → EP1 VLAN Steering — Full Diagnosis

Policy: CSBA_802.11X_NPS | SSID: NPS_80211X | WPA3-802.1X | RADIUS: CSBA_NPS at 10.152.0.11

Symptom: Authentication succeeds (EAP-Success at 9.14 s) but client always lands on VLAN1.

Troubleshooting Chain

  1. Confirmed NPS reachable from EP1 RADIUS test.
  2. Removed A3 (Extreme Networks NAC proxy) accidentally present in RADIUS server group — it was stripping or proxying attributes.
  3. EP1 classification rule had a trailing period: 5. vs NPS sending 5 — fixed.
  4. VOSS switch console password unknown — SSH blocked via IPE — EP1 has no CLI passthrough for VOSS — port config via EP1 Switch Template also unavailable due to GUI intermittency.
  5. Asked Karl for password — Karl unavailable until later in the week.
Root Cause 1 — NPS Sending Wrong Attributes The NPS Access-Accept (confirmed via wired pcap) contains three errors. The classification rule in EP1 never fires because the Filter-Id value does not match.
AttributeNPS SendsRequired (RFC 3580)Status
Filter-Id (11) KHLab Must match EP1 rule (EP1 was set to 5) ❌ Mismatch
Tunnel-Type (64) GRE (10) VLAN (13) ❌ Wrong
Tunnel-Medium-Type (65) IPv4 (1) 802 (6) ❌ Wrong
Tunnel-Private-Group-Id (81) 5, 6, 7, 8 (four values) One single value ❌ Ambiguous
Root Cause 2 — Staff VLAN Not Tagged on AP Port Even when EP1 correctly assigns a VLAN (confirmed in VLAN6 capture), the VOSS switch must have that VLAN tagged on the AP uplink port. It does not. The AP drops the tagged frame silently; the client falls back to native VLAN1.

Fixes Required

NPS side (Windows Server):

  • Change Filter-Id value to match EP1 classification rule exactly (either change NPS to 5 or update EP1 rule to KHLab).
  • Change Tunnel-Type → VLAN (13)
  • Change Tunnel-Medium-Type → IEEE 802 (6)
  • Send only ONE Tunnel-Private-Group-Id = target VLAN ID (e.g. 10 for Staff)

VOSS switch side (EN_5320) — requires Karl's console password:

show lldp neighbor                    # find AP port
vlan members add <Staff-VLAN-ID> <AP-port>
save config

VOSS Socratic

Fabric Connect Deep Dive — D1 & D2 Complete

D1 — Backbone Fundamentals

ConceptWhat You Learned
IS-IS control plane Builds LSDB (Link State Database) → Dijkstra → B-FIB. Every switch has identical full-fabric map. No STP blocking, all paths active.
MAC-in-MAC (802.1ah) Original Ethernet frame wrapped in outer backbone frame. Only B-MACs on the outer envelope. Intermediate switches never inspect client traffic.
B-MAC Zip code of the switch. Static, one per switch, configured once. IS-IS tracks which client MACs sit behind which B-MAC.
BEB vs BCB BEB (edge) = wraps/unwraps envelopes, knows C-MAC → B-MAC mapping. BCB (core) = forwards by B-DA only, never learns client MACs. Your lab = two BEBs, no BCB needed.
Anycast Gateway Same IP + deterministic MAC (derived from I-SID number) on all BEBs. Prevents trombone on client roam. All BEBs respond to ARP with identical answer — no election.
IS-IS vs STP IS-IS has extensible TLVs — carries I-SID membership, B-MACs, services. STP is purely loop-prevention with zero global view and no extension capability.

D2 — I-SID Service Model

ConceptWhat You Learned
VLAN vs I-SID VLAN = local construct. I-SID = fabric-wide membership ticket. Two switches with VLAN 50 cannot communicate unless both have vlan i-sid 50 100050. Same VLAN ID means nothing across the fabric without matching I-SID.
I-SID advertisement IS-IS TLV 185. Every switch knows which I-SIDs exist and which B-MACs belong to them. Flooding is scoped only to I-SID members — not the entire fabric.
Anycast MAC source Derived algorithmically from I-SID number — same input always produces same MAC. No manual coordination needed. All BEBs independently compute identical gateway MAC.
IS-IS IP Shortcuts isis ip-shortcuts extends IS-IS to distribute IPv4 routes across SPB. Without it, IS-IS only handles B-MAC forwarding. Required for Layer 3 Anycast routing to work.
Failover convergence IS-IS hello timers alone: ~9 s. IS-IS + BFD: ~300 ms sub-second detection and reconvergence. Anycast means other-BEB clients are unaffected when one BEB fails.
