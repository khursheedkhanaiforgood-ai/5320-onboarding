PPSK & PCG Deep Dive

The Dorm Room Architecture — Resolved from First Principles

The PPSK vs PCG distinction was worked through conversationally, arriving at a clean architectural model that maps directly to the Higher Ed dorm scenario.

PPSK alone — what it gives you

  • Unique key per student — one leaves, remove that PPSK, nobody else affected
  • No shared password problem — no mass reconnection event
  • Simple onboarding — key delivered via email/SMS before move-in day
  • Individual accountability — every device tied to a named student
What PPSK alone does NOT give you All students on the same SSID can still reach each other's devices. Student A can see Student B's laptop, printer, and gaming console. They're all on the same broadcast domain.

PCG — what it adds

Private Client Groups add the room boundary. Devices within the same PCG (same room) communicate freely. Devices in different PCGs are invisible to each other — enforced by hidden ACLs pushed by XIQ to the AP at the MAC address level. No VLAN per room. No firewall appliance. Done at the AP.

The dorm room model

ElementScopeEnforces
PPSKIndividual studentIdentity, onboarding, revocation
PCGRoom (group of students)Which devices can talk to each other
PPSK + PCGStudent in a roomBoth simultaneously

Key-Based PCG — the right mechanism for ceiling-mount APs

  • No anchor AP required — works on AP3000, no wall plate needed
  • No GRE tunnelling — simpler, lower overhead
  • Isolation enforced via hidden ACLs at the AP (MAC-level, below anything the student can touch)
  • XIQ pushes the ACLs automatically — IT configures PCG once in XIQ, AP handles the rest
  • IT never manages a MAC address list — the PPSK key is the identity

The onboarding flow end to end

IT creates Room 101 PCG in XIQ
  ↓
IT assigns 4 PPSKs to Room 101 PCG
  ↓
XIQ delivers each key to each student via email
  ↓
Student arrives on move-in day → connects to "Dorm-WiFi" → enters personal key
  ↓
AP places all their devices into Room 101 PCG automatically
  ↓
Done — IT never touched a MAC address, never visited a room
The one-liner for the demo "Think of PPSK as the student ID card — it identifies who you are. PCG is the room number — it defines your space. XIQ binds them together so the network knows both who you are and where you belong."

ACL — defined

Access Control List — a list of permit/deny rules that decides what traffic is allowed and what is blocked. In the PCG context, XIQ builds and pushes the list automatically. The student never sees it, configures it, or knows it exists.

Permit:  Room 101 MAC → Room 101 MAC   (roommates talk freely)
Deny:    Room 101 MAC → Room 102 MAC   (rooms invisible to each other)
