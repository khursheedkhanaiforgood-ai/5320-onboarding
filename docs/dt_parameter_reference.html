Overview — Source Tiers and the 60/15 Split

Every parameter in this reference belongs to one of four source tiers. The tier determines whether the AP reports it directly, whether it must be computed, or whether it can only come from the Design Parameter Manifest (DPM).

AP Direct Read verbatim from AP SSH poll — 5 commands, 5-second cycle
Computed Derived from one or more AP Direct fields in the collector or dashboard
Unavailable Not present in any AP3000 HiveOS show command
Static / DPM Site, client, or app context — not measurable from any single AP
The 60/15 split: The v3 simulator takes ~60 input parameters. Of those, 15 can be populated dynamically from live AP SSH data — the "15-Parameter Bridge" (§10). The remaining 45 are static site and client context from the DPM. See §10 and §11 for the full mapping.

§2 — Link Reliability

MAC-layer error rates and the HiveOS composite health score. These are the primary indicators of RF quality and collision pressure.

ParameterDefinitionStandard FormulaUnitsThresholds AP3000 CLI FieldTier
Link Score HiveOS composite link health. Four 25-point buckets summed: (1) CRC Error %, (2) Tx Retry %, (3) Frame Fail %, (4) Channel Utilization. Unknown field = 12.5 pts neutral. Higher = healthier. HiveOS proprietary — no IEEE clause sum(bucket_i) · each bucket 0–25 based on threshold bands 0–100 Good: 75–100 Warn: 50–74 Crit: <50 Reported in show interface as link_score AP Direct
CRC Error % Fraction of received frames failing the 802.11 Frame Check Sequence (FCS, CRC-32-MPEG2). Each CRC failure = one frame discarded. Primary indicator of RF noise, co-channel interference, or low SNR. AP3000 ACSP trigger threshold: 35%. 802.11-2020 §9.2.4.8 (FCS field: 4 octets, CRC-32) rx_crc_errors / rx_total_frames × 100 % Good: <2% Warn: 2–10% Crit: >10% ACSP trigger: 35% CRC error airtime percent= AP Direct
Frame Failure % Fraction of transmitted frames that ultimately failed — all retransmission attempts exhausted (Short/Long Retry Limit reached), frame dropped at MAC. Distinct from CRC (receive-side) and Retry (attempts before failure). High Frame Fail = persistent RF obstruction or hidden node. 802.11-2020 §9.3.2.10 (Short/Long Retry Limit; MSDU lifetime expiry) tx_pkt_errors / tx_packets_total × 100 % Good: <1% Warn: 1–5% Crit: >5% tx_pkt_errors / tx_packets (computed from counters). Note: tx_failed_pct is always None on AP3000 — use tx_error_pct. Computed
Tx Retry % Fraction of transmitted frames requiring at least one retransmission (Retry bit set in 802.11 Frame Control header, bit 11). A frame that retries and succeeds appears here but NOT in Frame Fail. High retry = degraded SNR or collision pressure that resolves before retry limit. 802.11-2020 §9.2.4.1.3 (Frame Control: Retry subfield, bit 11) tx_retry_count / tx_packets_total × 100 % Good: <10% Warn: 10–20% Crit: >20% Tx retry rate= (in show interface) AP Direct
CRC Airtime % Fraction of channel airtime consumed by frames that had CRC errors. Even corrupted frames consume spectrum during transmission. This metric captures the spectrum efficiency cost of bad frames — wasted airtime that could have carried good data. 802.11-2020 §11.11.9 (BSS channel utilization; CRC airtime contribution) airtime_of_crc_frames / total_channel_airtime × 100 % Good: <5% Warn: 5–15% Crit: >15% CRC error airtime percent= (direct CRC airtime metric, also used for CRC Error %) AP Direct

§3 — RF Health

Physical layer ambient noise measurement — the baseline from which all SNR calculations are derived.

ParameterDefinitionStandard MeasurementUnitsThresholds AP3000 CLI FieldTier
Noise Floor Ambient electromagnetic noise power measured by the radio during clear-channel periods (no active Tx or Rx). Combines thermal noise and in-band interference from non-802.11 sources (microwave ovens, Bluetooth, DECT phones, radar). SNR = Client RSSI − Noise Floor. 802.11-2020 §17.3.10.7 (OFDM RX sensitivity: −82 dBm min for 54 Mbps at 20 MHz)
802.11ax §27.3.12 (HE PHY sensitivity floors)
Thermal floor: N₀ = kTB = −174 dBm/Hz + 10·log(BW)		 Hardware ADC measurement reported by radio firmware during idle periods. Not computed. dBm Good: ≤ −90 dBm Warn: −90 to −75 dBm Crit: > −75 dBm (severe interference) AP3000 lab typical: −89 to −93 dBm (5 GHz) Noise floor=−89dBm AP Direct
SNR and MCS floor: SNR = client RSSI − Noise Floor. 802.11ax MCS 11 (1201 Mbps, 80 MHz, 2×2) requires SNR ≥ 30 dB. MCS 0 requires SNR ≥ 5 dB. The AP3000 radio profile sets Weak SNR threshold=15 dB — clients below this are capped at lower MCS tiers, directly reducing their throughput.

§4 — Airtime Detail

Fine-grained channel occupancy. 802.11 is half-duplex — while the radio transmits, it cannot receive. Tx + Rx airtime can sum to at most 100%. The AP3000 reports both cumulative (running average) and instantaneous (snapshot) variants.

ParameterDefinitionStandard UnitsNotesAP3000 CLITier
Rx Airtime % Fraction of time the radio detected valid 802.11 frames being received (from any source: BSS + OBSS). Includes management, control, and data frames. High Rx with low throughput = many overhead frames or corrupted frames being counted. 802.11-2020 §11.11.9 % Typically 10–40% on a busy AP. Saturated: 80–100%. Rx utilization= (cumulative) AP Direct
Tx Airtime % Fraction of time the radio was actively transmitting 802.11 frames (data, ACK, beacons, management). Beacons alone consume ~1–2% even on an idle AP. 802.11-2020 §11.11.9 % Heavy DL: 40–70%. Purely idle with beacons: ~2%. Tx utilization= (cumulative) AP Direct
ST Tx CU % Station transmit CU — subset of Tx Airtime attributable to uplink frames from associated clients. Difference from Tx Airtime = AP beacon and management overhead. 802.11-2020 §11.11.9 (per-STA contribution) % Always ≤ Tx Airtime %. ST Tx CU%= AP Direct
ST Rx CU % Station receive CU — airtime consumed delivering downlink data frames from AP to associated clients. Excludes broadcast/multicast and frames to disassociated clients. 802.11-2020 §11.11.9 % High = heavy video streaming or file delivery to clients. ST Rx CU%= AP Direct
Snap Tx CU % Instantaneous Tx CU at the moment of the last poll — not a rolling average. Reveals transient bursts that running averages smooth. Critical for detecting hidden-node collisions and short interference events. 802.11-2020 §11.11.9 (instantaneous vs RCPI average) % Can briefly hit 100% during burst transfers. Compare to Tx Airtime % to detect burstiness. Snap Tx CU%= AP Direct
Snap Rx CU % Instantaneous Rx CU at last poll. Large delta between Snap Rx and Rx Airtime = bursty interference (interference comes and goes between polls). 802.11-2020 §11.11.9 % Compare with Rx Airtime % to detect interference burst events. Snap Rx CU%= AP Direct

§5 — Channel Utilization

The formal 802.11k/RRM channel load measurements. The AP3000 uses these directly for Automatic Channel and Power Selection (ACSP). Configured trigger threshold for all three components: 35%.

ParameterDefinitionStandard FormulaUnitsThresholds AP3000 CLI FieldTier
Tx CU % Fraction of channel time AP was transmitting (all 802.11 frame types: data, management, control). Measured over hardware sampling window by radio CCA counter. 802.11k-2008 / 802.11-2020 §11.11.9 (Channel Load Report: BSS Load IE) tx_busy_time / total_time × 100 % Good: <30% Warn: 30–50% Crit: >50% Tx utilization=0% AP Direct
Rx CU % Fraction of channel time AP detected valid 802.11 preamble+PLCP that was successfully decoded (BSS + OBSS frames). This is the "useful signal" occupancy — compare with Int CU to understand signal-vs-noise balance. 802.11-2020 §11.11.9 (receive component — decoded frames) rx_busy_decoded / total_time × 100 % Good: <40% Warn: 40–60% Crit: >60% Rx utilization=3% AP Direct
Interference CU % Fraction of channel time the radio detected RF energy above the CCA threshold (−62 dBm default for 20 MHz OFDM) but could NOT decode it as valid 802.11. Sources: non-802.11 devices (DECT, microwave, Bluetooth), adjacent-channel leakage, hidden-node collisions, non-decodable OBSS frames. 802.11-2020 §17.3.10.6 (CCA Energy Detection: ED threshold ≥ −62 dBm for OFDM at 20 MHz)
802.11-2020 §11.11.9 (non-802.11 channel load)		 cca_busy_non_dot11 / total_time × 100 % Good: <10% Warn: 10–20% Crit: >20% ACSP trigger: 35% Interference utilization=7% AP Direct
Total CU % Sum of all channel occupancy: Tx + Rx + Interference. The single headline "how busy is this channel" metric. The AP3000 reports all four components independently — Total CU is their arithmetic sum. 802.11-2020 §11.11.9 (total channel occupancy) Tx CU + Rx CU + Int CU % Good: <50% Warn: 50–70% Crit: >70% Saturated stadium: 85–95% typical Total utilization=10% AP Direct

§9 — Feature Flags: HiveOS Proprietary

Extreme/Aerohive vendor extensions. No IEEE 802.11 standard clause. Behavior may differ from other vendor implementations.

Dyn CW Dynamic Contention Window. HiveOS extension of 802.11e EDCA. Normally CWmin/CWmax are static per AC (AC_BE: CWmin=4, CWmax=6 on AP3000). Dyn CW adjusts these dynamically based on real-time collision pressure. Under high load: larger CW = fewer collisions. Under low load: smaller CW = lower latency. OFF Dynamic CW=disabled
Hi-Dens High Density Mode. §12 — QoE Proxy Vector

QoE is not a single number. The FederatedTwinAgent computes a 5-dimensional vector from live AP data. The simulator produces a matching 5-vector. The delta is δ_calibration. When a user sets a target, δ_progress tracks movement toward that goal.

QoE-1
Throughput
avg Tx Mbps / station
Mean downlink throughput per associated client. Computed as total Tx Mbps ÷ station count. Ceiling = PHY rate × airtime efficiency.
QoE-2
Reliability
1 − CRC Error %
Fraction of frames delivered without PHY errors. Directly maps to user-perceived packet loss before TCP layer. 1.0 = perfect, 0.0 = total RF collapse.
QoE-3
Latency (proxy)
M/D/1: qd = 6u / (1 − u)
Queuing delay estimate via M/D/1 model where u = Total CU %. Not directly measurable from AP — model-derived approximation. True latency requires active probing.
QoE-4
Conn Quality
avg SNR → MCS tier
Mean SNR across clients maps to MCS index via AP3000 rate table. MCS 0–3 = poor, 4–7 = fair, 8–11 = good. Directly caps per-client throughput ceiling.
QoE-5
Capacity Headroom
1 − (Tx CU + Rx CU) / 100
Fraction of channel capacity not yet consumed. 1.0 = idle, 0.0 = saturated. Determines how many additional clients the AP can absorb before QoE degrades.
