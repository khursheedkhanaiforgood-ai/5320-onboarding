First Push Failure — Root Cause

Initial Supplemental CLI included create vlan and configure vlan ipaddress. EP1 creates VLANs via its own template mechanism first, then runs Supplemental CLI — so create vlan in Supplemental CLI hit an "already exists" error and failed the push. Fix: Supplemental CLI scope is DHCP-only. EP1 handles everything else natively.

Gaps Discovered — G-01, G-02, G-03

Three Production Gaps Found in Live Lab

G-01 Bin #1 — Switch Factory Reset

EP1 cannot factory reset EXOS switches. EP1 can reboot a switch remotely but cannot wipe config. AP factory reset IS available (EP1 → Devices → AP → Actions → Factory Reset). EXOS requires console/SSH: unconfigure switch all.

Client advice: Always retain console/SSH access to EXOS switches. Switch lifecycle management requires CLI for factory reset regardless of EP1 access level.

G-02 Bin #6/#9 — DHCP Server Activation Not Idempotent

enable dhcp ports cannot be in a reusable Supplemental CLI template. Works on first push (fresh factory reset). On re-push, EXOS throws error — push hangs. Must be removed from template before any policy re-push, or run manually once via SSH post-deploy.

Client advice: Two options — (1) include for initial deploy, remove before re-push; (2) run manually once after first push. Document this in every client handoff.

G-03 Bin #8 — EP1 Disables Ports on Policy Push

EP1 switch policy push administratively disabled Port 3 — the AP-facing trunk port. AP1 lost link, DHCP, IP, and CAPWAP tunnel. Appeared offline in EP1 despite white LED on physical device. Root cause: EP1 port template defaulted to admin-disabled for ports not explicitly set to enabled.

Fix: In EP1 switch policy port assignments, explicitly set Admin Enabled on every AP-facing and uplink port. After any switch policy push, verify with show ports X information detail — confirm Admin state: Enabled.

Recovery CLI used: enable port 3 then save configuration

Lessons Learned

Six Things Learned Today

  1. EP1 factory resets APs from UI — Monitor → Devices → AP → Actions → Factory Reset. No physical button needed. Physical pin is only needed when EP1 is unreachable.
  2. EP1 cannot factory reset EXOS switches — CLI only. Always keep console/SSH credentials in client handoff.
  3. EP1 natively enables IP forwarding on VLAN SVIs — XIQ did not. The f flag appears without any CLI.
  4. EP1 preserves underscores in VLAN names — VLAN5_Employee stays intact. XIQ used to silently drop underscores (Guest_100 → Guest100).
  5. Supplemental CLI scope is narrower than XIQ — EP1 handles VLAN creation, IPs, ports, ipforwarding natively. Supplemental CLI = DHCP pools only.
  6. After SSH key changes (factory reset): ssh-keygen -R <ip> clears the stale host key, then reconnect normally.
