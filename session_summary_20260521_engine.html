The Core Analogy — GPS Navigator for UI Configuration

The engine is not a document search, not a lookup table. It is a GPS navigator. XIQ is the starting map. EP1 is the destination. The engine knows every road, one-way street, and detour — including roads EP1 hasn't built yet (gaps). Per step: exact portal, exact left-nav item, exact tab, exact field label, exact dropdown value, exact button.

Version-Pair Architecture

All mappings are tagged to exact version pairs. XIQ-25.8.0→EP1-25.9.0 is stored entirely separately from XIQ-25.8.0→EP1-25.9.2. When ExtremeNetworks releases a new EP1 patch, admins trigger a re-scrape — the new pair is added as new data, not an overwrite. This is the engine's core promise: it ages gracefully as EP1 evolves.

Learning Framework

How the Engine Learns and Gets Better Over Time

The Core Insight

Two types of knowledge serve different purposes. Structural knowledge lives in Neo4j edge properties — the road quality map the engine reads before it moves. Semantic knowledge lives in pgvector — the pattern library the LLM draws on to explain and translate. Both must grow. Neither alone is sufficient.

Structural vs Semantic Knowledge

TypeWhere It LivesWhat It EnablesHow It Grows
StructuralNeo4j MAPS_TO edge propertiesNode 0 anticipatory path planning — reads road quality before traversalLab runs update confidence; scrape diffs restructure edges; curator corrections rebuild edges
Semanticpgvector — rag_chunks + confirmed_examplesLLM translation quality — few-shot context, explanation groundingPDF re-ingestion on doc update; curator corrections add high-weight examples

The Four Learning Mechanisms

#MechanismTypeTriggerEffect
1 Lab Validation — Edge Weight Update Structural Node 10 (Execution Agent) runs config on live lab update_c_lab(c_lab_prev, passed, n) updates c_lab on Neo4j edge. 5 passes → c_lab ≈ 1.0. One fail from 0.8 → 0.64 (asymmetric — harder to recover than to earn).
2 EP1 Patch — Graph Growth Structural Admin triggers re-scrape after new EP1 release Playwright finds new screens → new Neo4j nodes/edges created under new version pair. Previous version pair data preserved. Engine expands its map without overwriting history.
3 Confirmed Examples — Few-Shot Context Semantic Curator or lab confirms a mapping Row added to confirmed_examples with source, weight, version_pair. Node 4 (EP1 Translator) pulls nearest neighbours via pgvector cosine search → improves LLM translation quality.
4 HITL Curator Correction Structural Semantic Curator flags wrong nav path or missing step Neo4j edge restructured (structural fix) + new confirmed_example added with weight=2.0 (semantic fix). Dual-layer correction — the map is corrected and the translator learns the right answer.

The update_c_lab() Formula — Why It Works

def update_c_lab(c_lab_prev: float | None, passed: bool, n: int) -> float:
    result = 1.0 if passed else 0.0
    if c_lab_prev is None:
        return result
    return (c_lab_prev * (n - 1) + result) / n

# Examples:
# 5 consecutive passes:  c_lab → 1.0  ("battle-tested")
# From 0.8, one fail:    (0.8*4 + 0) / 5 = 0.64  (drops to WARN — must re-earn trust)
# Recovery:              (0.64*5 + 1) / 6 ≈ 0.70  (needs multiple passes to recover)

This asymmetry is intentional. Trust is earned slowly, lost quickly. A single lab failure should trigger curator review — not be silently averaged away.

Node 0 — Path Planner

The Anticipatory Engine — Redesigned After Architectural Scrutiny

The Problem That Was Raised

"There is NO way for the Lead AI Agent to anticipate the next step without having in memory something similar. This seems counterintuitive to learning. Take Google Maps — it does not know how to go from A to B but executes commands based on what is stored. Learning MUST be encoded somehow."

The Architectural Correction

The original design used confirmed_examples (pgvector semantic search) as the primary learning mechanism. This is reactive — it finds similar past trips but cannot give Node 0 anticipatory awareness of road quality ahead. Edge weights on Neo4j MAPS_TO relationships ARE the encoded structural memory. Node 0 must read the full route quality map before moving a single step.

Node 0 — Two-Phase Design

PhaseWhat HappensOutput
Phase 1: PLAN Full Cypher path traversal on Neo4j — reads all MAPS_TO edge weights before execution begins. Computes path_confidence = min(edge.confidence). Identifies gap_edges and warn_edges. Generates human-readable route_preview. route_preview → HITL Gate → user confirms before any step fires
Phase 2: EXECUTE Only after hitl_gate_passed=True. Routes to Node 1 (Intent Parser) to begin step-by-step traversal. Each step already has its expected confidence — no surprises mid-route. Step-by-step EP1 nav cards with confidence per step

The Neo4j Path Query — Road Quality Map

MATCH path = (start:XIQScreen {screen_id: $seed_id})
             -[:MAPS_TO*]->
             (end:EP1Screen {screen_id: $destination_id})
WHERE ALL(r IN relationships(path) WHERE r.version_pair = $version_pair)
RETURN path,
       [r IN relationships(path) | r.confidence] AS edge_confidences,
       reduce(min_c = 1.0, r IN relationships(path) |
              CASE WHEN r.confidence < min_c
              THEN r.confidence ELSE min_c END) AS path_confidence,
       [r IN relationships(path) WHERE r.confidence < 0.40  | r] AS gap_edges,
       [r IN relationships(path) WHERE r.confidence >= 0.40
        AND r.confidence < 0.70 | r] AS warn_edges

Neo4j MAPS_TO Edge Properties — The Road Quality Metrics

PropertyTypeMeaning
confidenceFloatWeighted Σ(w×c)/Σ(w) — overall step reliability
c_doc, c_gui, c_labFloatIndividual layer scores — diagnose why confidence is low
traversal_countIntHow many times this edge has been traversed
success_countIntHow many traversals succeeded (lab or HITL-accepted)
last_validatedDateWhen was c_lab last updated — staleness signal
sourceEnumlab | curator | scrape — provenance of confidence
version_pairString"XIQ-25.8.0__EP1-25.9.0" — version isolation key

HITL — Two Levels, Not One

LevelWhenPurpose
Level 1 — Upfront GateAfter Phase 1, before any executionUser sees route_preview with worst-case path_confidence and gap warnings. Confirms before engine moves.
Level 2 — Mid-Traversal PauseNode 6 detects GAP during executionLangGraph interrupts at gap edge. Curator reviews, corrects nav path, resumes from checkpoint.
